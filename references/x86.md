# x86-64 assembly workout curriculum

Use GNU assembler syntax (AT&T) for x86-64 Linux. This track is freestanding: no libc, no C runtime, raw Linux syscalls, and the System V ABI when a function is called from a test harness. Pick the level at session start and keep every exercise inside its scope. Each exercise targets one main idea and optionally one adjacent concept. State the register and memory contract up front, and never write the instruction sequence for the user.

The host is assumed to be x86-64 Linux. The validator runs the binary natively, or through `qemu-x86_64` when the host is another architecture.

## Setup

Default location: `~/workouts/x86/<topic>-<YYYYMMDD-HHMM>`. The track is invoked as `asm/x86`, which resolves to the `x86` id used by the files, validator, and workout directory.

Create the scaffold with the skill's setup script:

```sh
"$CLAUDE_SKILL_DIR/scripts/new-workout.sh" asm/x86 <topic>
"$CLAUDE_SKILL_DIR/scripts/new-workout.sh" --dir ~/workouts/x86/<slug> asm/x86 <topic>
```

It creates the directory, `main.s`, a `Makefile`, an empty `testdata/`, and a `TASK.md` scaffold, then prints the workout directory. It never writes into an existing directory. Do not create these by hand.

Fallback when the script is unavailable:

```sh
mkdir -p ~/workouts/x86
mkdir ~/workouts/x86/<slug>
```

The validator stays in the skill at `scripts/validate-x86.sh` (default install: `~/.claude/skills/workout-programming/scripts/validate-x86.sh`). Do not copy it into the workout directory.

Start from `main.s`:

```asm
    .section .text
    .global _start

_start:
    # Scaffold stub: exits with status 1 so validation fails until the task is done.
    mov $1, %edi
    mov $60, %eax
    syscall

    .section .note.GNU-stack,"",@progbits
```

Use `.global` (`.globl` also works), the `_start` entry point, and the `.note.GNU-stack` section in every `.s` file. Check the toolchain with `as --version`, `ld --version`, and `cc --version`.

The copied `Makefile` is a convenience shortcut, not the validator. `make run` assembles and links every `.s` file, runs the program, and prints its exit status; a non-zero status is the result, not a make failure. When a `.c` harness is present, it links through `cc` instead. `make test` runs `scripts/validate-x86.sh` on the directory, and `make clean` removes the objects and the binary.

## Syntax and ABI

AT&T syntax: `op src, dst`, `%` prefixes registers, `$` prefixes immediates, and `#` starts a comment.

- Registers are 64-bit `rax` to `r15`, with `eax`/`ax`/`al` views of `rax`, and the same pattern for the others.
- Linux syscall: number in `rax`, arguments in `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9`, result in `rax`, and `rcx`/`r11` are clobbered. Use `syscall`.
- SysV function call: arguments in `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`, integer return in `rax`, and `rdx:rax` for a 128-bit return.
- Callee-saved registers: `rbx`, `rbp`, `r12` to `r15`. Every other general register is caller-saved.
- `cmp src, dst` computes `dst - src` and sets the flags; the conditional jump is read in that order.
- The stack must be 16-byte aligned immediately before a `call`.

## Test scaffold

Choose one of two shapes per task.

**Function tasks** use a small C harness, `tests.c`, that calls the assembly function and checks the result. The harness is provided and is not the exercise. The user's file exports the function and defines no `_start`.

```asm
    .section .text
    .global add
    .type add, @function

# long add(long a, long b)
add:
    # TODO: replace this stub.
    xor %eax, %eax
    ret

    .size add, .-add

    .section .note.GNU-stack,"",@progbits
```

```c
#include <stdio.h>

long add(long a, long b);

static int failures;

static void check(long a, long b, long want) {
    long got = add(a, b);
    if (got != want) {
        fprintf(stderr, "add(%ld, %ld) = %ld, want %ld\n", a, b, got, want);
        failures++;
    }
}

int main(void) {
    check(2, 3, 5);
    check(0, 0, 0);
    check(-1, 1, 0);

    if (failures != 0) {
        return 1;
    }
    printf("all cases passed\n");
    return 0;
}
```

The stub returns 0, so the harness compiles and its checks fail before the user starts. Keep the harness to roughly 30 to 50 lines, use at least three cases (typical, zero or empty, one edge case), and deliberately leave one meaningful case untested.

**Program tasks** define `_start` and have no `.c` file. The validator links with `ld` and checks the exit status. Ask for output through the `write` syscall when the task needs it.

## Code scope

- **Easy:** at most 20 lines of user code in `main.s`, one main construct.
- **Medium:** at most 100 lines of user code, usually in `main.s`, optionally one extra `.s` file.
- **Hard:** a small program spread over multiple files. Name the files and pass them to the validator.

"User code" counts the instruction and data lines the user writes. Directives, the provided stub, the test harness, and the `.note.GNU-stack` section do not count.

## Validation

Run the skill's validator against the workout directory:

```sh
"$CLAUDE_SKILL_DIR/scripts/validate-x86.sh" ~/workouts/x86/<slug>
EXPECT_EXIT=42 "$CLAUDE_SKILL_DIR/scripts/validate-x86.sh" ~/workouts/x86/<slug>
```

The directory is optional and defaults to the current directory. Remaining arguments are source files. Without them, every `.s` file is assembled and every `.c` file is used as the harness. The script runs, in order:

- `as --64 -g` for each `.s` file.
- With a `.c` harness: `cc -fno-pie -no-pie -Wall -Wextra -Wpedantic -o main <objects> <harness>`. Without one: `ld -e _start -o main <objects>`.
- `./main` with a 10 second timeout. Override it with `RUN_TIMEOUT=30`.
- A comparison of the exit status with `EXPECT_EXIT`, default `0`.

It prints the raw tool output and a summary, and exits non-zero when a required check fails. The `ld` executable-stack warning is reported as a `NOTE` that points at `.note.GNU-stack`. Report exact tool messages. Do not run the individual commands yourself, and do not copy the script into the workout directory.

## Easy: registers and straight-line code (max 20 lines)

- Register sizes and aliases: `rax`/`eax`/`ax`/`al`
- `mov`, immediates, `movabsq`, register to memory and back
- `add`, `sub`, `inc`, `dec`, `neg`
- `and`, `or`, `xor`, `not`, `shl`, `shr`, `sar`
- `cmp`, `test`, and one conditional jump
- Counted loops with `dec` and `jnz`
- `push`/`pop` and one `call`/`ret`
- `.data`, `.bss`, `lea`, and RIP-relative operands
- The `exit` syscall and its status

Example themes: exit with the sum of two values; exit with the larger of two values; count down a register; absolute value with `neg` and `cmovs`; set a register from a comparison with `setcc`; sum an array of bytes; write a fixed string with the `write` syscall; swap two stack slots.

## Medium: functions, widths, and syscalls (max 100 lines)

- Prologue and epilogue, `rbp` frame, saving callee-saved registers
- SysV argument registers, return value, and stack alignment
- Local buffers on the stack, bounds, and cleanup
- Byte, word, dword, and qword accesses; `movsx`/`movzx`
- `imul`, `mul`, `div`, `idiv`, `cqo`
- Addressing modes: base, index, scale, displacement
- `openat`, `read`, `write`, `close`, and error returns in `rax`
- Byte and string loops with `rep movsb`, `rep stosb`, `scasb`
- `argc`/`argv` on the stack at `_start`
- Calling a C function from assembly

Example themes: `strlen`; `strcmp`; reverse a buffer in place; count a byte in a buffer; uppercase a buffer; copy a file; exit with the number of lines read; sum the integers in `argv`; print a small number in decimal; call `write` with a stack buffer.

## Hard: small system utilities (multi-file)

- Program structure across `main.s` plus focused files such as `string.s`, `io.s`, or `convert.s`
- `strlen`, `strcmp`, `memcpy`, `memset` written from scratch
- Decimal and hexadecimal conversion with output through `write`
- A small utility such as `cat`, `wc`, or `hexdump`
- Mixed C and assembly, with the ABI respected on both sides
- `brk` or `mmap` for a buffer larger than the stack
- Syscall error handling and exit status propagation

Example themes: `cat` that copies standard input to standard output; `wc -l` over files named in `argv`; `hexdump` of a buffer; `itoa` plus `write` for signed decimal; a C driver calling assembly string routines; a program that reads a file into an `mmap` region and exits with its line count.

## Accuracy and safety checks

- Writing a 32-bit register such as `eax` zeroes the upper 32 bits of `rax`; writing a 16-bit or 8-bit register does not.
- `movq $imm` accepts only a sign-extended 32-bit immediate; use `movabsq` for a full 64-bit constant.
- `cmp src, dst` subtracts `src` from `dst`. Do not read `jl` and `jg` as if the operands were reversed.
- Signed and unsigned comparisons use different jumps: `jl`/`jg` versus `jb`/`ja`.
- `idiv` divides `rdx:rax`; sign-extend `rax` into `rdx` with `cqo`, and check for a zero divisor, which traps.
- Keep the stack 16-byte aligned before `call`, and restore `rsp` before `ret`.
- A `syscall` clobbers `rcx` and `r11`; do not keep loop state there across it.
- A failed syscall returns a negative value between -4095 and -1 in `rax`.
- Exit statuses are 0 to 255; a computed value outside that range is truncated.
- `_start` has no return address, so it must exit explicitly; never fall through.
- Add `.note.GNU-stack` to every file so the linker does not mark the stack executable.
- Prefer RIP-relative `symbol(%rip)` addressing; use `-no-pie` when the task links with `cc` and uses absolute addresses.
- Never use `int $0x80` on x86-64; it selects the 32-bit ABI. Use `syscall`.
- If an easy or medium task grows past its line budget, move the task up a level instead of bending the scope.
